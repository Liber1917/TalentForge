# TalentForge — MVP 设计规格 (SPEC)

> 状态：计划阶段产出，待用户复核。本文是 SDD 的规格源头，后续每个里程碑再落 `docs/spec-m{N}-*.md` 细化。

## 0. 定位与北极星

TalentForge 是**全生命周期求职平台 × 陪伴式决策助手**：帮信息类求职者**想清楚投什么、为什么、差距在哪、怎么补**——同时**锻造人才**，而非迎合市场。

- **北极星**：锻造人才（非迎合市场）。增强用户**认识世界、改造世界**的能力。
- **身份**：批判意识的**助产士**，不是马克思主义教师——方法是**提问式**（弗莱雷《被压迫者教育学》），不是灌输。说教是异化的另一种形式。
- **一句话**：系统不替你投，也不给你灌真理；它陪你看清自己、看清结构，然后你自己决定。

## 1. 目标用户与范围

- **用户**：信息类同学（计算机 / 自动化，校招 / 应届）。单人本地工具，非多用户 SaaS。
- **MVP 形态**：端到端最小垂直切片——显式输入 → 画像 → Boss 单源抓取 → 胜任力建模 → 三维匹配 → 三元决策 → 反思性对话 → 反馈回流。
- **自动投递**：MVP 后再定（不在 MVP，不移植 jobclaw applier/）。
- **岗位源**：MVP 做 Boss 单源；架构保留 SourceAdapter 多源扩展点，未来加牛客 / 校招官网。

## 3. 系统架构与模块划分

### 3.1 模块

```
talentforge/
├── profile/      # 画像（双轨+结构位置）           [可拓展 · Protocol + 默认实现]
├── competency/   # 岗位胜任力建模                  [可拓展 · Protocol + 默认实现]
├── field/        # 场域建模（政治经济学/结构性风险） [可拓展 · Protocol + 默认实现]
├── sources/      # 岗位源适配器（Boss 单源）        [可拓展 · SourceAdapter 协议]
├── matcher/      # 三维匹配                        [可拓展 · Protocol + 默认实现]
├── decision/     # 三元决策 + 可解释链 + 结构性追问   [稳定核心 · 锁定]
├── feedback/     # 反馈闭环（显示性偏好回流+叙事修正） [稳定核心 · 锁定]
├── storage/      # SQLite + JSON state             [基础设施]
├── api/ web/ cli.py extension/  # 四端交互         [表面]
```

### 3.2 稳定核心 vs 可拓展外围（D15）

- **稳定核心（锁定，不设扩展接口）**：`decision/`（三元决策 + 可解释链 + 结构性追问）、`feedback/`（显示性偏好回流 + 叙事修正）。
- **可拓展外围（每个研究层暴露 Protocol + 默认实现，可替换实验）**：
  - `profile/` — 画像机制未定论（O1：5 层 / 3 层 / 2 层 + 结构位置维度）
  - `competency/` — TalentModel-skill 未经理论审视（O2），须可替换
  - `field/` — 场域建模全新、无上游，最不确定，须可替换
  - `matcher/` — 量化方法未定论（O2：序数 / 基数 / 显示性偏好）
  - `sources/` — 岗位源适配器（已有 SourceAdapter 协议思路）
- **实现方式**：依赖倒置。`decision/` 与 `feedback/` 只依赖 schema 类型（§5 数据模型 = 稳定契约），不依赖任何具体实现。研究层内部实现可整层替换而不碰核心。

### 3.3 移植映射（融合两个仓库 + 一个技能资产）

| 模块 | 移植来源 | 移植 vs 重写 |
|---|---|---|
| `profile/` | OpenBiliClaw `soul/` + `memory/` | 移植机制（事件入嵌、分析器、JSON state），重写领域（taxonomy/prompts/字段）+ 双轨 + 结构维度重构 |
| `competency/` | TalentModel-skill（SKILL.md + references/） | 挂载为子代理资产；经理论审视后重写；额外产结构化 JSON 版 |
| `field/` | **无上游** | 全新设计（政治经济学 + 结构性风险信号库） |
| `sources/` | jobclaw `scraper/` 思路 + OpenBiliClaw `sources/` 协议 | 采 SourceAdapter 协议 + 插件真实会话只读采集（反爬更稳） |
| `matcher/` | jobclaw `matcher/` | 参考结构，重写量化方法（O2） |
| `decision/` | **独有层** | 全新 |
| `feedback/` | OpenBiliClaw 反馈调度机制（EventProcessingScheduler/ProfileUpdatePipeline 思路） | 移植机制，重写信号语义（显示性偏好 + 叙事修正） |
| `storage/` | OpenBiliClaw `storage/` | 移植 SQLite 思路，精简 |
| 四端 | OpenBiliClaw 同层 | 移植形态，内容域重写；插件薄化为 Boss 只读 content script |

## 5. 数据模型（稳定契约）

> 这些 schema 类型（Pydantic）是稳定核心与可拓展外围之间的契约。外围生产/消费这些实体，核心只依赖这些类型。

```
【Profile 画像】（双轨 + 结构维度）
├─ 显式层：简历 / 技能 / 期望 / 目标 / deal-breakers
├─ 人格叙事轨：身份、价值观、深层驱动、认知风格（自然语言 + 结构化字段）
├─ 偏好/效用轨：岗位属性偏好序（序数，非基数）
├─ 结构位置：物质条件、社会关系、所处资本积累环节
└─ 显示性偏好历史：投/拒/接offer 的行为流

【Field 场域】（独立建模，无上游）
├─ 行业/公司政治经济学画像
├─ 结构性风险信号库：996/大小周/无社保/竞业… + 政治经济学解释
└─ 主流意识形态识别：「996 是福报」「自我优化」等叙事

【Job 岗位】（扩展 jobclaw Job 模型）
├─ 基础：source/title/company/location/url/description/salary/tags
└─ 结构字段：公司类型 / 行业 / 是否996 / 社保 / 工作模式

【CompetencyModel 胜任力框架】
├─ 岗位侧：6 维度 + 行为锚点 + 证据（结构化 JSON，非仅 HTML）
└─ 候选人侧：同维度下的自我证据

【Match 匹配结果】（三维）
├─ 市场契合（量化方法 = O2 待定）
├─ 成长契合（岗位推进个人叙事）
└─ 结构认知（岗位在结构中的位置 + 风险信号）

【Decision 决策】
├─ verdict：投 / 观望 / 不投（三维象限判定）
├─ 可解释链：画像证据 × 胜任力维度 × JD 原文 + 结构性反思
├─ 差距 + 补短板（锻造落点）
└─ 结构性追问（反思性对话的钩子）

【FeedbackEvent 反馈事件】
├─ 用户决策 + 结果（面试/被拒/offer）+ 对话自述
└─ → 回流：显示性偏好（效用轨）+ 叙事修正（叙事轨）
```

## 6. 核心机制

### 6.1 决策判定（三维评估，二维象限 + 结构调制）

> 注：本节细化 D12 的「三维」——前两维（市场契合 × 成长契合）构成决策象限，第三维「结构认知」作为**调制项**而非第三根轴（避免 2×2×2 八象限过度复杂）。

"投/观望/不投"由三维评估驱动：

| | 成长契合高 | 成长契合低 |
|---|---|---|
| **市场契合高** | 投 | 观望（提醒：舒适区） |
| **市场契合低** | 观望/投（挑战型机会） | 不投（或触 deal-breaker 硬边界） |

第三维「结构认知」不独立成轴，而是**调制**前两维：结构性风险信号（996/无社保/竞业…）强制降级 verdict 或至少在可解释链中显式警示（"蠢事提醒"）。

### 6.2 反思性决策对话（人在闭环，D11）

- 每张决策卡附带一个**结构性追问**（是问题，不是答案），如："你上次说想避免 996，但连续三次都投了大小周岗位——你现在的优先级变了吗？"
- 用户用对话回应（苏格拉底式），系统追问、假设、确认、调整。移植 OpenBiliClaw 的苏格拉底对话**机制**，重写追问**内容**。

### 6.3 批判层（D12–D14，横切关注点）

- **结构位置**：双轨每一轨都结构化理解——叙事是"我在这结构中成为了谁"，偏好是"我的欲望被这结构如何塑造"。
- **场域**：独立建模劳动力市场的政治经济学（结构、矛盾、意识形态）。
- **世界观/认识论/方法论**：不输出教条，组织追问框架。从第一个切片内置，非后加。

## 7. 交互面（D7）

- **CLI**：一次性的决策报告 + 命令驱动。
- **本地 Web**：决策卡、反思对话、画像查看、反馈主界面。
- **浏览器插件**：Boss 真实会话**只读采集**（JD 浏览 + 投递/沟通动作），MVP 用薄 content script，不做 OpenBiliClaw 的 10 平台任务调度机器。

## 8. 错误处理与边界

- **合规红线**：只读采集；检测到验证码/风控**暂停等人工**；不绕过反爬；不自动投递（MVP）。
- **结构性风险显式**：996/大小周/无社保等不单是黑名单，带政治经济学解释。
- **数据本地**：SQLite 本机；无遥测；无云端账号。
- **可解释性**：每个决策必须可回溯——画像证据 × 胜任力维度 × JD 原文。
- **冷启动失败**：显式输入缺失时，系统显式要求补齐，而非静默用空画像跑。

## 9. 测试策略

- **单测**：schema 校验、决策象限规则、偏好序、结构性风险信号。
- **集成**：Boss 只读抓取验收（登录授权下 ≥20 条，O4 派生）。
- **反思/对话质量**：三元决策的可解释链 + 结构性追问的"提问式而非说教"（LLM-as-judge 或人工抽检）。
- **研究层替换性**：每个 Protocol 至少一个 mock 实现，验证 decision/feedback 不因外围替换而破坏（D15 的护栏）。

## 10. 里程碑分解

> 每里程碑先落 `docs/spec-m{N}-*.md`，确认后实现；原子 commit，conventional message。

- **M0 骨架 + 稳定契约**：§5 schema 类型 + §3.2 Protocol 定义 + 端到端空壳（显式输入 → 空决策 → 空报告）。
- **M1 画像 + 胜任力**：`profile/` 显式版默认实现（双轨 + 结构位置）+ `competency/` 挂载 TalentModel-skill（结构化 JSON 版）。
- **M2 数据 + 匹配**：`sources/` Boss 单源只读抓取 + `field/` 最小结构性风险信号库 + `matcher/` 三维匹配默认实现。
- **M3 决策 + 反馈**：`decision/` 三元 + 可解释链 + 结构性追问 + `feedback/` 显示性偏好回流闭环。

## 11. 悬置问题（触发时机见各条，单独探讨）

### O1 — 画像层深度：如何移植 OpenBiliClaw 灵魂机制
- 背景：五层自进化依赖海量内容事件，求职域信号稀疏 1–2 个数量级。
- 候选：A 完整五层 / B 三层 / C 两层最简。
- 硬约束（D10/D12）：人的模型必须容纳叙事轨 + 效用轨 + 结构位置 + 场域（后两者超 OpenBiliClaw 五层，无上游）。
- 触发时机：M1（soul 里程碑）规划前。

### O2 — 匹配 × 胜任力量化方法
- 背景：TalentModel-skill 未经理论审视；需引入理论根基。
- 方向：单边偏好建模 + 显示性偏好 + 序数打分（pairwise/learning-to-rank）+ 学界量表（BARS/Likert）。
- 硬约束（D10/D12）：匹配是三维（市场/成长/结构），非一维分数。
- 触发时机：M2（matcher 里程碑）规划前。

## 12. 技术栈

- 后端 Python 3.11+；数据 SQLite + JSON state；API FastAPI；配置 pydantic-settings。
- 前端 TypeScript 插件（MV3）；Web 静态 SPA。
- 自研轻量管线，不用 LangChain/LangGraph；LLM 多 provider（复用 OpenBiliClaw llm/ 实例链思路）。
- 单人本地部署，无云。
