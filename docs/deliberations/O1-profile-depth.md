# O1 — 画像层深度：如何移植 OpenBiliClaw 灵魂机制

- 状态：accepted（R0-R3 完成，小确认 1/2/3 全部裁决，2026-08-20；FCP 由决裁人本对话行使）
- 决裁人：用户　作者：Sisyphus

- 触发条件：M1（soul 里程碑）规划前（spec §11）

## 1. 背景与问题（Context）

### 1.1 上游事实（已核实的代码事实，非文档转述）

OpenBiliClaw 的"五层灵魂"在文档与代码中**已分叉**：

- **文档模型**（spec.md §2.1.2）：事件→偏好→觉察→洞察→灵魂，五层网状双向修正。
- **代码模型**（soul/profile.py:612 OnionProfile）：洋葱五层 **Core→Values→Interest→Role→Surface**（内稳外变），外加两个 ephemeral 层 `recent_awareness`（觉察笔记）与 `active_insights`（洞察假设），以及 `personality_portrait` 自然语言画像。
- 洋葱的稳定层本身很轻（几组 `list[str]` + MBTI + 权重标签）。真正重、吃海量事件的是**三个 LLM 分析器的高频自进化循环**：PreferenceAnalyzer（分块+预算装箱，1543 行）、AwarenessAnalyzer、InsightAnalyzer，加 Speculator（2056 行，双探针）、Consolidator（1806 行，12h 整理）、ProfileUpdatePipeline（1899 行，事件驱动增量）。

### 1.2 TalentForge 的既定约束

- **D6 显式优先**：简历/配置为主输入，行为流仅增量修正——因为求职域信号稀疏 1–2 个数量级（一天投几个岗 vs 一天看几十个视频）。
- **D10/D12 双轨+结构**：人的模型必须容纳人格叙事轨 + 偏好/效用轨 + 结构位置 + 场域。后两者超 OpenBiliClaw 五层，无上游可移植。
- **D13 提问式**：批判层是组织追问的框架，非灌输教条。
- **D15 稳定核心+可拓展外围**：profile/ 属可拓展外围（Protocol 化），M0 已定义 `ProfileEngine.build_profile / update_from_feedback` 接口与三轨 Profile schema。
- **M0 契约现状**：`Profile` = 显式层 + `narrative`（叙事轨）+ `utility_preferences`（序数偏好）+ `structural_position` + `revealed_preferences`（行为流）。

### 1.3 问题陈述

M1 的 ProfileEngine 默认实现应采用什么画像机制？具体要回答：

1. **结构**：沿用 OpenBiliClaw 洋葱五层？简化为三层？还是 M0 三轨即结构？
2. **分析器**：三个 LLM 分析器（偏好/觉察/洞察）在显式优先下各自的角色？
3. **子机制取舍**：闭集词表 / 生命周期状态机 / 证据链 / overrides / 假设机制（validated hypothesis）/ consolidator / speculator，哪些进 M1？
4. **结构位置与场域**怎么进画像（无上游）？

## 3. 候选项（Options）

### Option A：洋葱五层全移植（领域重写）

沿用 Core→Values→Interest→Role→Surface + 觉察/洞察 ephemeral 层，重写 taxonomy/prompts/字段为求职域，三分析器+consolidator 全套移植。

- Good：机制最完整；叙事深度最高；与上游同步演化容易。
- Bad：结构位置/场域仍要硬塞（上游没有）；三分析器高频循环在稀疏信号下空转；M1 工程量最大；洋葱的"兴趣域权重"结构与序数偏好错配（内容消费是主题导向，求职是属性导向）。

### Option B：三层（事件 + 偏好 + 职业自我认知）

保留事件层（SQLite）+ 偏好层 + 认知层（觉察/洞察/灵魂合并），显式输入直接写认知层，行为流只做偏好增量与稀疏推断；砍 speculator/awareness 日记/12h consolidator。

- Good：匹配信号密度；认知层单层承载叙事轨；砍掉空转循环。
- Bad：认知层内不分层会重蹈"一锅粥"（叙事/价值观/结构位置混在一个 JSON 里）；"三层"与 M0 已有的三轨 schema 关系需重新映射；合并后的洞察→沉淀路径变隐式。

### Option C：结构即 M0 三轨 + 借四个子机制（+可选假设机制）

不移植洋葱结构；Profile schema 维持"显式层 + 叙事轨 + 效用轨 + 结构位置 + 行为流"；从 OpenBiliClaw 借：闭集词表（岗位属性/类别归一）、生命周期状态机（trial→active→decaying→archived）、证据链（evidence_count + source 引用，喂 Dv6）、overrides 覆盖层；可选借 InsightHypothesis 做叙事主张的"假设→验证→沉淀"。

- Good：契约零破坏（Dv4）；工程量最小（Dv5）；序数偏好原生（Dv3）；研究可替换（Dv7）。
- Bad：叙事深度天花板低（无觉察/洞察逐级蒸馏，叙事主张靠单跳 LLM 推断）；"结构位置/场域"字段仍空设计；假设机制若进 M1 会增加对话结算复杂度（上游 11-kind 结算队列就是为它长出来的）。

## 4. 初步建议 + Drawbacks（先写 Drawbacks）

### Drawbacks（对建议的反驳，先于建议本身）

1. **"砍到几层"可能问错了问题**：五层/三层/两层的争论聚焦结构，但上游真正的价值在机制（词表/生命周期/证据链/overrides）。如果机制才是本质，结构之争是伪问题——但若机制离了分层结构就不成立（如证据链依附于层间晋升），Option C 拆机制搬就会失灵。
2. **叙事深度不可逆**：砍掉觉察/洞察蒸馏，叙事轨只能从简历+对话单跳推断。若 M2/M3 发现决策链需要更深的"为什么是他"论证，回补蒸馏管线的成本可能高于 M1 就建轻量版。
3. **结构位置与场域在三个选项里都只是"待设计"**：真正的理论新 territory（D12）没有任何选项给出方案——本研讨可能只解决了一半问题。
4. **假设机制与反思对话（D11）的耦合深度未验证**：上游把假设验证做成了 11-kind 结算队列（重工程）。若 M1 引入轻量假设，M3 的反思对话会依赖它；若 M1 不引入，M3 的追问素材从哪来（纯当轮生成）未论证。

### 初步建议（作者倾向，待 R1 检验）

Option C 为底，**但**吸收 B 的一个修正：叙事轨内部引入"轻蒸馏"（对话/反馈产生的叙事主张先进 trial 态，经用户确认或二次证据才 active）——即把"假设机制"作为 Option C 的必选而非可选，用状态机而非结算队列实现（轻量版）。结构位置/场域留独立子问题（O1a）在 R2 后定。

### R2 裁决记录

决裁人在 R2 中作出以下裁决（对话记录见会话）：

1. **Option C 为底**：M0 三轨 schema 即结构，借机制不搬洋葱。——通过（小确认 1）
2. **假设机制 = 方案 α**（合并版，最简状态机 + provisional）：
   - 契约：M0 原字段零改动；`NarrativeClaim`（state/evidence_count/source/confidence）作 Profile 可选附加字段 `narrative_claims`
   - M1 只做 trial + archived 两态，无晋升流
   - 隐式确认：对话回复/反馈自动累积证据到 evidence_count
   - active 态推迟到 M3，补晋升流时晋升必须经用户确认（反"后台灌输"红线）
   - provisional：M3 用真实数据检验，无价值则整体移除
3. **读人方法 = 精神分析式**（决裁人提出，超出 R1 评审范围的新方向）：
   - 通过分析用户**消化的内容**（看/收藏/停留）与**生产的内容**（写过/说过/怎么说）理解用户的欲望结构（爱欲结构），包括未被自己意识到的部分
   - 方法论与 TalentModel-skill 的拉康式临床画像入口（Phase 0L"听你怎么说话"）同源——候选人言语方式本身是第一层证据
   - R1"信号密度不足"论据被修正：素材多少与质量因人而异，**具体问题具体分析**，系统不预设素材充裕或贫乏
4. **素材 = 路线 b（内容采集）+ 国内平台清单**：
   - 沿用 OpenBiliClaw 的采集机制（插件真实会话只读采集）
   - 平台清单（8 个，砍掉 YouTube/X/Reddit 三个海外源）：B站、知乎、小红书、抖音、微博、V2EX、Bangumi、Linux.do
   - 牛客不在 OpenBiliClaw 清单内，属 M2 岗位源，如需采集单独加

### R3 补充 2：证据话语五要素（决裁人裁决，2026-08-20）

决裁人指出"议价地位可能高估了，要不要看看？"属**不含信息的废话**——把侦察任务踢回用户。检索 SBI（CCL 情境-行为-影响反馈模型）与 SPIKES（肿瘤科坏消息六步协议）后综合为**证据话语五要素**，将作为 M3 反思对话/认知修正提示词的**硬性 schema 约束**（结构化字段，缺项=不合格输出，可程序校验）：

1. **锚点**（SBI-S）：用户何时填了什么主张——修正的起点
2. **观察**（SBI-B，只讲观察不贴标签）：可验证数据列表
3. **对照**（证据原则）：和什么比，带样本量与时间窗；无对照的数据无信息量
4. **冲击的诚实命名**（SPIKES-K）：差距意味着什么，就事论事不判人
5. **可行动分叉**（SPIKES-S + 提问式）：2-3 条已侦察完的路 + "数据哪里不对？"的否决权交还

外加两条 SPIKES 前置：**先问认知再给修正**（探到否认/回避不硬灌）；**坏消息先预警**（"我有个和你判断不一样的发现"）。理论注脚：Radical Candor 洞见——消息越难说，人越倾向含糊；含糊正是废话的来源，故用 schema 强制清晰。

### R3：结构位置（StructuralPosition）设计（2026-08-20，决裁人裁决"现在设计"）

**定位**：档案第三栏——"你站在哪里，被什么推着"。是叙事轨/效用轨的地基：同一愿望在不同处境下意义不同（志向 vs 奢侈）。决策（投/观望/不投）必须读地基。

**八个格子**（理论来源：马克思政治经济学 + 西方马克思主义计量经济学；标准：能实际改变某个岗位判断，否则不设）：

| # | 格子 | 内容 | 理论 |
|---|---|---|---|
| 1 | 现金流缓冲 | 无收入可撑时长（≤3月/6月/1年/2年+） | 劳动力再生产储备 |
| 2 | 当前身份/约束 | 在读年级/在职/间隔期；城市、住宿、家庭责任 | 形势约束（应届身份是国内真实资产） |
| 3 | 支持网络 | 导师/学长/家庭/内推人——布迪厄式社会资本存量 | 求职靠关系网流动 |
| 4 | 依赖与承担 | 经济独立程度、是否反哺家庭 | 风险承受力由义务决定，非意愿 |
| 5 | 定价底牌 | 保留工资（用户填）+ 议价地位（**系统估**） | 劳动力商品价格形成 |
| 6 | 剥削敏感带 | 知情接受度刻度：996/大小周/on-call/加班费模糊/竞业条款（毒中之毒——限制未来出卖劳动力的自由）。绝不容忍项 → 决策硬否决 | 剩余价值榨取形式清单；"知情"二字：不道德审判，逼你看清每份工资里拿什么换的 |
| 7 | 再生产账单 | 住房（城市绑定）/通勤/饮食成本 + 技能折旧速度（知识半衰期、35岁危机行业版） | 工资毛收入 vs 净积累（25k深汕 vs 20k成都可能反转） |
| 8 | 流动性与时点 | 敢不敢裸辞（用户填）+ 周期位置（**系统估**：校招窗口/行业周期） | 议价地位是时变变量；格子5记价格，格子8记价格往哪走 |

**证据原则**（决裁人原话："信息不对称是剥削的一环！我们讲究一个证据"）：

- 信息不对称本身是被剥削的一环——用户恰恰是市场行情最没信息的一方，行情判断不能靠用户自填
- 格子 5/8 的市场侧（议价地位、周期位置、薪资分布、供需）**由系统从 M2 岗位数据流估**——数据可抓取，估算须给证据（样本量、来源、时间窗），不拍脑袋
- 用户只填"自己那半"：保留工资、敢不敢裸辞、现金流、约束、敏感带刻度

**填充机制**（沿用两轨 + 硬软分级）：

- **用户直填**：格子 1–8 的用户侧。冷启动一次填好（简历信息素格式），偶尔更新
- **素材猜→待定池**（α 机制）：软线索——反复看"裸辞/FIRE/考公"内容 → 待定"经济焦虑/退路考量活跃"（记证据链，不下结论）；收藏全是大厂面经 → 待定"目标带锚定头部"（是欲望还是从众？留给反思对话问）
- **系统估算**：格子 5/8 市场侧，M2 数据到位后启用，每项带证据标注
- **三条红线**：①猜的只进待定池，永不直接写进正式格；②物质条件类硬信息系统不猜（猜错"撑3个月"比不写危害大）；③每条线索带证据链，反思对话可摊开"我为什么这么猜"

**与决策的接口**（设计意图，M3 落地）：格子 6 绝不容忍项 → 硬否决（已有机制）；格子 1/5/7/8 联合调制"观望"的语义（现金流紧+议价弱 → 观望提示偏向行动；缓冲足+周期向上 → 观望可延长）；格子 3/4 影响补短板建议的可行性排序（"先问内推人" vs "先刷题"）
