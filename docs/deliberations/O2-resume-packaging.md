# O2 — 简历包装的画像学处理

- 状态：accepted（R0-R2 + FCP 完成，2026-08-21）
- 决裁人：用户　作者：Sisyphus
- 视角面板（理论密度高 → 5 视角，≥3 主模型）：信号密度 / 工程成本 / 理论严谨 / 产品价值 / 契约稳定性
- 触发条件：M1 画像已完成（简历 bootstrap 已落地），校对交互设计前

## 1. 背景与问题（Context）

### 1.1 问题来源

用户指出：简历大多有包装成分，且**包装是劳动力市场的正当生存策略**——没有合理包装，很多人找不到工作；更有"年轻人为就业针对性学习、包装、最后成为高潜力人才"的真实成长路径。因此：

- 系统**不能**把"简历有包装"当作人岗匹配的减分项（判死刑）；
- 但也不能把包装内容当**未经核实的事实**进画像（D17 证据链纪律）。

### 1.2 已确立的相关约束

- **D11 反思对话**：对话是画像的验证渠道（"对话即蒸馏"）。
- **D13 锻造人才**：包装先行→能力跟上，是"锻造"的正面用例（潜力时间窗）。
- **D17 证据原则**：信息不对称是剥削的一环；硬信息系统不猜；猜测只进待定池带证据链。
- **D3/O2 序数偏好**：不做"包装度 70 分"式假精确。
- **D19 读人方法**：精神分析式——"怎么包装自己"本身是欲望结构的暴露。

### 1.3 核心张力

| 立场 | 内容 |
|---|---|
| 包装是信号 | 一个人怎么包装自己，暴露他想象中"市场要什么"（欲望结构） |
| 包装是正当策略 | 没有包装找不到工作；包装是入场券，不是原罪 |
| 包装可能是虚假 | 事实性夸大若当事实进画像，污染决策链（证据纪律） |
| 包装可能是成长 | 包装先行→学习→胜任，是真实路径，潜力应被看见 |

### 1.4 问题陈述

画像系统应如何**处理**简历包装？具体四个子问题：

1. **匹配判定**：包装是否影响、如何影响人岗匹配（投/观望/不投）？
2. **事实纪律**：包装中的事实性主张如何标记、如何升级为 verified？
3. **读人价值**：包装风格是否作为叙事轨素材（欲望结构暴露）？
4. **潜力追踪**："包装先行"的成长路径如何建模（时间窗、验证、升级）？

## 3. 候选项（Options）

### Option A：包装=中性待验证（作者倾向）

- 匹配：包装**不影响**匹配判定（不扣分不判死刑）
- 事实纪律：简历主张默认 `unverified`，经对话验证后升级 `verified`
- 读人：包装风格原样记录为叙事轨素材（"呈现风格：强调产出/程度偏乐观"），仅定性标注
- 潜力：`unverified`→`verified` 的升级轨迹本身就是潜力证据；给"包装先行"者潜力时间窗

### Option B：包装=信号分级

- 匹配：包装轻度影响匹配（如"程度膨胀"条目在匹配时打折）
- 事实纪律：同 A（unverified→verified）
- 读人：同 A
- 潜力：同 A

### Option C：包装=剥离矫正

- 匹配：包装内容在进匹配前被"去包装"（剥掉膨胀词再评估）
- 事实纪律：同 A
- 读人：不记录包装风格（视为噪声）
- 潜力：不追踪

## 4. 初步建议 + Drawbacks（先写 Drawbacks）

### Drawbacks（对 A 的反驳）

1. **A 可能过度宽容**：完全不扣分，会不会让"纯吹"简历与扎实简历同分？若验证环节稀疏（用户不常对话），unverified 主张长期挂着，会不会等于默认信任？
2. **对话验证的负担**：每条 unverified 都要对话验证，验证链条会不会过长、用户疲劳（同 O1 α 的确认负担教训）？
3. **潜力时间窗的边界**：给"包装先行"者时间窗，多久合理？会不会被滥用为"无限期宽容"？
4. **B 与 A 的界限模糊**：如果验证升级后 A 与 B 的匹配结果趋同，分级是否只是仪式？

## 5. R1 独立评审聚合表（R1 已完成，2026-08-20）

| 视角 | 评审模型 | 立场 | 关键论点 |
|---|---|---|---|
| 信号密度 | 主模型 | 支持 A | A 是唯一在稀疏对话下自洽的：unverified 不判死刑、匹配照常、验证慢慢补。**攻击**：验证链（逐条对话质询）是 O1 确认负担的 2 倍，真实节奏下会长期挂 unverified，D17 证据纪律只剩纸面。缓解：验证优先级分级——高风险硬指标主张（精通X/主导Y）优先验证，低风险主张直接进 trial |
| 工程成本 | 主模型 | 支持 A（第一阶段只做加法） | 对话验证入口是成本大头，且撞契约（协议方法 vs 稳定核心）。缓解：verified 加进 Literal（兼容旧 trial/archived）+ presentation_style 加进 NarrativeIdentity（兼容）+ FeedbackEvent 加可选 verify_claims 字段（additive，默认空）——不新增协议方法 |
| 理论严谨 | 主模型 | 支持 A+修正 | ①升级触发必须是证据（对话验证/行为印证），不是时间——时间自动升级会漂移成默认信任；②unverified 主张不得进入硬字段推导（verified_skills 与 claimed_skills 分离建模，匹配算法只读前者），否则 D17 全破；③包装风格记录语言必须中性（"强调产出"是观察，"爱吹牛"是评判），且可被用户反驳 |
| 产品价值 | flash | 有条件支持 A | A 对纯匹配用户完全隐形（无价值也无摩擦），但 unverified 主张仍全权重进匹配=隐性默认信任；B/C 是可见惩罚违背 Dv1。**攻击**：最大风险是"惩罚延迟到被拒时刻、以信任损失加倍支付"；潜力轨迹对纯匹配者不可见、MVP 难兑现。缓解：验证多源化（feedback/behavior 源契约已有）+ 待验证显式可见+自助验证路径 + 时间窗硬边界 + 教练式对话框架 |
| 契约稳定性 | flash | A 可行但需红线 | verified 不得进 Literal（state 是生命周期轴 trial→active→archived，verified 是证据轴，正交；改 Literal 破坏穷举消费方）。**攻击**：M0 无对话事件载体，最大诱惑是扩展锁定核心的 FeedbackEvent——必须显式禁止。缓解：验证用新增默认值字段或由 evidence_count/sources 推导（sources.kind 已有 dialogue）；验证流走 ProfileEngine 新增外围方法+外围事件类型（有界破坏）；包装风格做 NarrativeIdentity 可选字段；严禁修改 feedback/ 与 FeedbackEvent |

## 6. 未决分歧（R1 产出）

**收敛点（五视角一致）**：
1. Option A 为底（不判死刑、unverified 待验证、包装风格入叙事轨、潜力轨迹）。
2. 验证机制必须**多源化**——不能只靠对话（对话稀疏），要同时吃反馈事件/行为（契约 ClaimSource 已有 feedback/behavior 源）。
3. **契约红线**：不碰 FeedbackEvent / feedback/（锁定核心）；verified 不进 Literal；新增字段全部 additive 带默认值。
4. 潜力时间窗必须有**硬边界**（未验证即 archived），防无限期宽容。

**真分歧（R2 裁决点）**：
- **验证实现的归属**：工程成本视角主张"FeedbackEvent 加可选 verify_claims 字段（additive）"；契约稳定视角主张"走 ProfileEngine 新增外围方法+外围事件类型，FeedbackEvent 字节不动"。两者冲突——前者动核心（虽然 additive），后者动外围协议。
- **匹配权重缝隙**：产品价值视角点破 A 的未定义处——unverified 主张是否全权重参与市场契合？"包装不影响匹配"与"主张照常计入匹配"矛盾。这决定 A 是"中性"还是"隐性默认信任"。
- **验证优先级分级**（信号密度）vs **全部主张进 trial**（工程成本）——低风险主张要不要直接信任。

## 7. 决议（R2 完成，2026-08-21，FCP 由决裁人本对话行使 → accepted）

### 决裁记录（对话原文要点）

决裁人两个关键补充，纳入最终方案：
1. **软话慢慢验证**："软话慢慢验证，反正有信号？"——所有主张（不分硬/软）统一走 α 机制：挂"待验证"，靠日常信号（行为/反馈/对话）慢慢累积证据转正；对话只是信号之一（最贵、最少用），不是唯一通道。
2. **能力随时间变化**："人的能力素质等都会随时间变化"——主张转正后不是永久有效，需时效管理；画像不是静态档案而是带时间戳的轨迹；潜力判断看变化率而非快照。

### 最终方案（O2 决议）

1. **包装=中性**：不判死刑、不扣分、不进匹配公式做惩罚项（Dv1/Dv2）。包装风格原样记录为叙事轨素材（中性语言，可被用户反驳）。
2. **统一主张机制（α 全量）**：简历所有主张（硬指标与软话）默认 `trial/unverified`；证据累积（多源：行为/反馈/对话/用户上传证明）达阈值转正 `verified`；低风险主张靠慢信号，高风险硬指标可加对话快验。
3. **时效管理（新增，借鉴 OpenBiliClaw 时效三态）**：转正主张带有效期，到期进入待复审，复审不过/荒废则过期/降级——能力会变，验证非一次性。
4. **匹配只吃"证据够了"的主张**：`verified_skills` 等硬字段仅已验证主张可入；未验证主张只作参考与叙事，不进匹配推导（分开记账，非二元而是"证据充分度"）。
5. **潜力=变化率**：追踪主张与技能随时间的变化轨迹（verified_at/复审史），潜力判断看趋势（涨/平/降）而非当前快照——"包装先行→学习→胜任"正是上升轨迹的正面用例。
6. **契约红线**：严禁修改 feedback/ 与 FeedbackEvent（锁定核心）；verified 不并入 Literal（与 lifecycle 轴正交）；新增字段全部 additive 带默认值；验证/信号累积走 ProfileEngine 新增外围方法 + 外围事件类型（有界破坏）。
7. **时间窗硬边界**：潜力时间窗设明确期限（一个校招周期），到期未验证即 archived——防无限期宽容。

### 与 O1 的衔接

- O2 的"统一主张机制"即 O1 α 机制的全量应用（O1 只做了叙事轨 claims，O2 扩展到全部主张）
- 时效三态借鉴 OpenBiliClaw（O1 已定"借机制"）
- 潜力=变化率 与 D13 锻造立场（包装可被证明成真本事）闭环
